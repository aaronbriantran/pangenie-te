I get two lists of the samples from the big HPRCv2 biallelic callset and the small HPRCv1 biallelic callset. Then, I grep the matches between them:

<code>grep -f small_samples.txt big_samples.txt > matches.txt</code>

Looking at the <code>wc -l </code> of the matches.txt and the small_samples.txt shows 43 and 44 respectively, and using:

Changing to HPRCv2 fixes the low samples issue, but it looks like phase_common still needs AC/AN tags anyways. I downloaded bcftools for myself. Using the documentation from the HPC wiki, I downloaded bcftools and htslib to <code>/scratch/devtools</code> and added <code>PATH=/scratch/devtools/bcftools:$PATH</code> and <code>BCFTOOLS_PLUGINS=/scratch/devtools/bcftools/plugins</code> to <code>~/.bashrc</code> so that the PATH now looks for my installation of bcftools first when scanning for bcftools. It also has the BCFTOOLS_PLUGINS variable set up so that the <code>bcftools +fill_tags</code> plugin can be run. This special path can be overwritten by Conda or module load, so this shouldn't affect reproducibility when explicitly loading these systems (as they prepend their paths directly to PATH when loaded, so they overwrite my edit to ./bashrc, which runs at login only). However, that means I need to run these without module load.

To make the panel viable for tag filling, I run this to convert to a BCF:
<code>bcftools view --threads 4 -Ob -o biallelic_v2_filled.bcf biallelic_v2.vcf.gz</code>

Then I run:
<code>bcftools +fill-tags biallelic_v2.bcf -Ob -o biallelic_v2_filled.bcf -- -t AN,AC</code>

These have been added to rules of Snakemake.
