## New approach to the breakpoint analysis

I had been working for the past few days on performing breakpoint analysis by using <code>bwa mem</code> and using the samtools suite to analyze the resulting bams. The idea is to isolate where the TEs are using Xiaoyu's L1ME-AID results, get their coordinates in T2T, and find the corresponding coordinates in the bcftools consensus haplotypes. Then we can examine the bams at those locations and find alignments that sit at the edge of these TEs, and find the number of reads over that area.

We can define a null too--maybe assuming even sampling over a location? Then we can compare the distributions of reads between null, uninserted, and inserted TE.

This is pretty difficult because you need to convert coordinates, phase reads between multiple haplotypes, and handle the coordinate conversion for each haplotype. It was possible because bcftools consensus actually produces chain files that let you shift coordinates, but then you need a whole other tool for that. Things just get messy, so Juan pointed out an easier solution.

## Using vgtools to do read phasing and determine valid insertions

The core idea is to construct a diploid graph from a sample VCF and align WGS reads directly to that graph, and then genotype variants.

A few things get handled when we instead construct a diploid graph:

* shifting coordinates for insertions are automatically handled by node IDs in a graph.
* we don't have to build the graph later when we phase RNA-seq reads and use RPVG. Again, one of the best advantages of a graph is natively handling shifts in alignments
* we don't have to account for haplotype contigs, etc., we can have direct access to haplotype paths.
* we can use <code>vg call</code> genotyping directly! **On the assumption that reads won't map inside the body of TEs due to multimapping**, genotypable structural variants are those with a read pileup on the edges of their nodes--that is, they are supported by a breakpoint!

## General flow

I implemented the following process for sample F1 as follows:

* split up combined sample bcf into per-sample vcfs using <code>bcftools +split</code>.
* tabix them and split per chromosome using bcftools view and tabix those.
* use them with vgtools autoindex to create giraffe mapping indices
* map reads to the resultant graph, and call using vg pack and call with genotyping.
* overlap variants per haplotype with L1ME-AID potential TEs (HAP^TE)
* overlap TEs per hap with vg callset (HAP^TE^VG and HAP^TE^!VG subsets of HAP^TE)

Xiaoyu merges a bunch of VCFs per individual together based on interval, not based on allele identity. Presumably this is due to slight differences in the actual alleles themselves, or the repetitive sequences that RepeatMasker identifies per individual. Besides, we should expect variation as TEs get older, so it would be hard to cleanly match on alleles. In the best case, we would be able to do pangenome analysis on a multiple sequence alignment (i.e. on top of a pangenome) but c'est la vie.

Based on my analysis from the lab meeting slides, I think it's best if we use the slop radius of 100 (the most stringent) and use the matches on variant length and type (INS or DEL).

The reasoning and code around the previous intersection effort weren't well documented, so I've had to replicate that work moving forward.

First, I:

```bash
bedtools slop -i l1meaid_hprc2_te.bed -g /scratch/atran/final/3_pangenie/input_files/CHM13v11Y.fa.fai -b 100 > slop_limeaid.bed
```

to Xiaoyu's L1ME-AID population level annotations. Most of the time, the interval describes the consensus start and end positions of the TE, but sometimes it only describes the range of start positions! This causes a lot of trouble, especially since start positions vary. We slop it to add 50 bp prior to the starting position to make sure that TEs with slightly different starting positions can be included when we do the next step.

Next, we use:

```bash
bcftools view ../5_phasing/results/phased_complete.bcf | bedtools intersect -a stdin -b inputs/slop_limeaid.bed -wo > any_phased_repeat_intersect.txt
```

VCFs report only the starting position. So we intersect all variants with the slopped positions to find variants that start within 100 bp of the interval defined by the bed file.

Finally, we run scripts/match_records.sh, a Claude creation that quickly awks through the file and removes records where (INS/DEL) are not the same and the variant length is not within 10% of one another. We get this info from the variant ID string in the VCF columns and the columns of Xiaoyu's bed file. We can quickly grab the header again with:

```bash
bcftools view -h ../5_phasing/results/phased_complete.bcf | cat - matched_vcf_body.txt > matched_phased.vcf
```

That's **3402 TEs as a set between all 3 samples**, which is about 1000 TEs per individual. Xiaoyu thinks he can get 2000, but Juan reported about 1000 per person in his use of BICAN data from PanGenie, which isn't so bad!

We can filter this VCF by sample and haplotype:

```bash
bcftools view -s F1 matched_phased.vcf | bcftools view -i '(GT="1|0") || (GT="1|1")' - > F1_matched_pat.vcf
```

Yielding the paternal haplotype. Of course, we can also modify for mat. That yields about 200 or so TEs per haplotype, heterozygous or homozygous at that locus. Of them, we get maybe 100-150 heterozygous loci prior to breakpoint analysis.
