The Xiaoyu based pipeline merges all of the annotations as a single bed file. We can overlap it with the combined.vcf, which is just the combined genotypes of the three samples F1, F2, and M1.

```bash
bcftools view ../5_phasing/results/combine_vcfs/combined.bcf > combined.vcf

bcftools view -i "GT='alt' && ID~'INS'" combined.vcf | bedtools intersect -a stdin -b ../6_breakpoint/inputs/limeaid_ins_slop.bed -wo > results/xiaoyu/slop_intersect.txt
```

We can then use match_records to prune on length and whether they and the bed file are both INS (non-reference). This should yield a VCF subset of combined.vcf!

```bash
bash ../6_breakpoint/scripts/match_records.sh results/xiaoyu/slop_intersect.txt results/xiaoyu/intersect_length_pruned.txt
```

And we can append a header easily.

```bash
cat <(bcftools view -h combined.vcf) results/xiaoyu/intersect_length_pruned.txt results/xiaoyu/intersect.vcf
```

Juan wanted some evidence to prove that !X ^ !RP is not the same as !X ^ !RP. We would have to integrate multiple sources of evidence (distance from Xiaoyu features, comparison of difference in lengths).

Comparing multiple variables is a bit much so we do the simplest thing:

We define !X^RP as one sample, and !X^!RP as another sample. They each have a distribution of the random variable D, distance to the nearest Xiaoyu bedfile feature (consensus polymorphic MEI insertion). We can use the Kolmogorov-Smirnov 2-sample test to see if the sample of values of D in !X^!RP comes from the same distribution that generated the sample !X^!RP. That is, do indels that RepeatMasker thinks are polymorphic show up closer to (or further away from) consensus features than indels that RepeatMasker does not think are polymorphic?
