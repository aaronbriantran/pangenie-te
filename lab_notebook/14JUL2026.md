## 3 - vg^PanGenie per hap per individual (breakpoint verified)

Now that we have phased haplotypes per hap, we will need to call variants from the diploid graph to see what TEs we get back. We will draw from [the vgtools info on SV calling](<https://github.com/vgteam/vg/wiki/SV-Genotyping-and-variant-calling>).

I want to genotype the VCF directly because it ensures the representation of variants is exactly the same as the VCF that created the graph, and I'm worried about position changes messing with my overlaps. The unfortunate issue is that <code>vg autoindex</code> doesn't work with genotyping from the VCF. I implemented a new diploid graph construction script at <code>scripts/manual_diploid_graphs.sh</code>. It should be easy to modify <code>map_reads.sh</code> as well to map reads afterwards. This is also a good way to update to a consistent version of vg.

I'll run this as a separate option while I run the normal genotyping, and I also do some of the TE comparisons for Juan.

### TE comparisons

We can run the same comparisons that we did on the phased set on the unphased set of F1 and get a general idea of what we're working with.

```bash
bcftools view /scratch/atran/final/3_pangenie/vcfs/F1_genotyping_biallelic.vcf | bedtools intersect -a stdin -b inputs/slop_limeaid.bed -wo > results/te_match/any_unphased_repeat_intersect.txt
```

We can run scripts/match_records_unphased.sh (the same as match_records.sh, just with slightly different pathing and column definitions).

```bash
bcftools view -h /scratch/atran/final/3_pangenie/vcfs/F1_genotyping_biallelic.vcf | cat - matched_vcf_body.txt > matched_unphased.vcf
```

The issue with this approach is that we are definitely over-favoring location and length as valid determinants of when variants match. This process implies **38035 TEs** unphased in F1 alone! Of those, this process would claim that only **3402** TEs are in the _complete phase set_, of which a mere 200 belong to F1's paternal haplotype. This simply can't be right.

We will need to filter on allele.
