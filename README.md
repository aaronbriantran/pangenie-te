# Pangenie TE Analysis

## Context
This repository includes code related to work for identifying eQTLs in an ASE analysis of polymorphic TEs, taken from a family duo of iPSCs as described in Quaid et al. (2025). The following describes the ideal pipeline:

## Code
This analysis was not finished. In this code, I:

1. impute all variants, including structural variants, via PanGenie and the human pangenome (HPRCv1.1)
2. annotate variants via RepeatMasker
3. annotate transposable elements via L1ME-AID, as described by the HGSVC in Logsdon et al. (2025).
4. phase all variants via SHAPEIT, using statistical phasing and lineage phasing
5. validate identified TEs with overlaps against consensus TE positions and lengths in HPRCv2
6. validate TE genotyping and phasing by constructing a phased diploid graph and genotyping from it using the vgtools toolkit.

Below, each step of the analysis, relevant code, and reasoning behind the decisions are described.

Then, I discuss general intuitions and findings generated by this process, and how that might apply in the future.

Finally, I provide some context and consider future applications of this line of work.

## Analysis Flow

### FastQC
Code in <code>1_fastqc</code> refers to a simple run of FastQC to determine the quality of WGS reads.

### Genotyping
Although <code>2_genotyping_depr</code> is deprecated, the code is correct. It simply runs the basic PanGenie analysis flow, indexing variants with index.sh, genotyping per sample with pangenie.sh, and writing it to a multiallelic VCF with vcfoutput.sh. To convert to biallelic representations (necessary for any downstream tasks in manipulating VCFs) I finally use biallelic.sh.

All the scripts in the <code>vcfs</code> folder use simple bcftools commands to subset the VCFs for use later, collect basic statistics, and calculate the heterozygosity ratio.

### Repeat Annotations
The repeat annotation directory <code>3_repeatanno</code> is also fairly simple. bcftools merge should be used to merge the variant calls of all samples together and extract the non-reference insertions. That VCF should be run through makefasta.sh to simply extract the insertion sequences, label them with names based on their positions, and write them in FASTA format. Then repeatmasker.sh and limeaid.sh. By using name labels derived from the variant name, we can match these annotations with our phased VCFs in the next step.

### Phasing
The phasing workflow in <code>5_phasing</code> uses a Snakemake pipeline.

It takes the VCF samples, combines them, indexes it, and fills its AN and AC tags. It takes in the HPRCv2 pangenome as a phasing panel. HPRCv1 is essentially a subset of HPRCv2, but HPRCv2 has enough samples to satisfy SHAPEIT, which won't do anything below 50 samples (recall that HPRCv1 has 88 haplotypes, or 44 samples). We can then do common variant phasing on it (rare variants are typically not very phasable without meaningful representation in the panel, but unlike SNPs there wouldn't be any meaningful sample sizes for rare SVs, which are very rare and ensconced in common SNP variation).

The inputs (recombination maps and family files) were adapted separately. Since this is only a duo, a family file is trivial to construct alone. The recombination map refers to a recombination map for the T2T assembly (Lalli, Bortvin, McCoy, and Werling 2025).

### Breakpoint
In <code>6_breakpoint</code>, I use vg to construct a diploid graph based off of the genotyped variants from PanGenie. I can then map reads from the WGS fasta directly onto the diploid graph with a reference backbone and then call variants and see if the called variants are concordant with the genotyped variants.

This works off the assumption that reads for TEs probably do not map in the interior of the TEs due to their repetitive nature (there should be natural multimapping in polymorphic TEs across TE loci). Therefore, we can assert that reads should pile up at the breakpoints of the polymorphic TE insertions. These half-reference reads should thus inform vg if the variant can be called compared to the reference backbone at a given locus.

It is possible that the pileup is not at the breakpoint. It is possible to use a chain file along with bedtools to check pileups adjusted for the size changes from SVs. I would prefer to use vg to visualize pileups, but I have not found a tool in vg that makes that easy.

### Analysis, Decisions, and Results

The analysis scripts <code>filter_eval_3.ipynb</code> and <code>plotting_gq_uk.ipynb</code> respectively describe why I dropped checking flanking sequence in RepeatMasker and why I dropped filtering for GQ when looking at PanGenie calls. There are also some summary statistics for TEs.

Of additional interest will be the work I did after figuring out the breakpoint analyses and seeing what TEs remain phased. The files in <code>lab_notebook</code> describe:

- 5AUG2026 describes the concordance of breakpoint vg calls with PanGenie genotypes.
- 13JUL2026 describes how to overlap identified TEs with consensus TEs in HPRCv2 described in Xiaoyu Zhuo's pipeline [INTACT_MEI](https://github.com/xzhuo/INTACT_MEI/tree/main), which is cited within.
- 20JUL2026 and 21JUL2026 put together everything. Check here for numbers on phased, consensus, breakpoint-validated TEs.
- AUG13_2026 describes running Xiaoyu's L1ME-AID pipeline directly on my own data, and checking whether there is any overlap between my and Xiaoyu's annotations. This attempts to remove the effects any possible issues my own workflow would have. The analysis script test_distances.py in <code>3_repeatanno</code> is also described here--I find a p-value of essentially 0.

## Future
The endpoint of this work is that the accurate phasing of structural variants is still quite difficult because appropriate panels for phasing still don't have a large enough sample size, and thus can't provide the linkage information necessary for robust phasing. There were some phased elements, however, suggesting that it is at least feasible to do phasing that way.

Those interested in the use of the pangenome for downstream tasks may also find the broad design of this pipeline relevant. Using vg as a form of breakpoint analysis will be useful for those in the field. Already, people in this area are interested in faster, cleaner, more efficient pipelines for the inference of personalized genomes from pangenomes, with the potential to heavily alleviate reference bias (see the work of Ben Langmead's lab, Vaddadi et al. (2026) and Lin, Iyer, Chen, and Langmead (2024)).

So, pangenomes are great at genotyping polymorphic TEs but suffer from a lack of sample size in phasing them, diminishing the impact of minimized reference bias because ASE analyses are not easily performed without phasing. Phasing tools like SHAPEIT expect large, biobank scale panels, so any tools leveraging the pangenome for its structural variation and phasing benefits will probably need to build methods that can handle very large pangenomes quickly (see, for example, the work of the Gymrek lab).

More generally, pangenomes are effective at the recovery of variants that short read data typically struggle with, which should be of considerable interest to anyone interested in rare variation. The recovery of this rare variation significantly improves the precision of subsequent transcriptomic mapping methods, and therefore anyone interested in the use of bulk transcriptomic data should also be interested. Signals from bulk sequencing can also inform single cell experiments, although it remains to be seen if pangenomic methods can apply to single cell, given its weaker resolution compared to bulk sequencing (of interest will be Cuomo et al. (2023)).
